# Configurable controls verification — 2026-10-25

## Implementation

Home → Open dashboard preserves Home/Sensors/Projects/Settings navigation.
Add/edit/reorder/delete widgets, save private layouts, explicitly enable/disable
publishing. Supported types: Bool/String buttons, Bool switch, Float64 slider and
Twist joystick. Relevant settings only appear for the selected widget. Native
Android Views and this project's rcl/Cyclone runtime; no ROS-Mobile code/artwork,
ROS 1 master, rosbridge or extra runner. Installed ROS-Mobile was not accessed.

The foreground sensor service owns control publishers. A bounded latest-value
slot per widget is consumed at 20 Hz; no unbounded UI command queue. Joystick UI
renews every 100 ms, returns zero on release/cancel/focus loss, and a worker-side
300 ms lease sends zero if renewals stop. Pause/navigation disables all controls
and removes those publishers after a zero Twist request. Sensor/Agent lifetime
is independent. Robot-side command expiry remains necessary for phone/network
failure. Buttons are one-shot latest-value commands, not exactly-once events.

Reproduce with a PC observer started before the device tests (same ROS domain):

```bash
ROS_DOMAIN_ID=0 ./tools/pc-ros.sh --interface PC_IP -- python3 tools/pc-controls-probe.py
# In another terminal, with the project screen foreground and unlocked:
./setup/build.sh :app:connectedDebugAndroidTest \
  -Pandroid.testInstrumentationRunnerArguments.class=dev.ros2android.android.ControlsTest
```

## Limits

One reference phone and standard schemas only. There is no arbitrary ROSIDL field
editor, custom message generation, multiple named dashboards or layout import/
export. Switch state is local input, not subscribed robot feedback. Not all
widget types have a complete end-to-end UI-to-wire gesture trial: backend Bool,
String, Float64 and Twist paths and the stated UI behaviors are checked. Full
TalkBack, all phone sizes/orientations, motor safety and network-loss endurance
remain separate qualification. Emergency stop cannot be guaranteed by a final
wireless/USB ROS message alone.
