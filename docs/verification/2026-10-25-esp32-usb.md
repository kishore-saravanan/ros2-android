# Reference ESP32 USB transport verification — 2026-10-25

## Implemented

- Main app Settings → Microcontrollers → Start USB agent. One Agent transport at
  a time; the existing Stop action applies to either mode. The service requests
  Android USB permission and claims only one supported CP2102 interface.
- CP2102 reference driver: 115200 baud, 8N1, no flow control, deasserted DTR/RTS,
  bounded bulk transfers, two pumps, app-owned raw PTY, packaged upstream serial
  Agent. No root or Linux Agent. UART output contains only upstream XRCE frames.
- Detach stops the Agent/USB bridge; status requests reconnect and explicit Start.
  Sensors/workspaces retain their independent lifetimes.
- Serial firmware uses the same battery subscription, heartbeat and display
  acknowledgement as Wi-Fi, with a separate build cache and no Wi-Fi credentials.
  The firmware's default ROS domain is 0; profile override supports 0–101.

## Actual checks

- `setup/build.sh`: assembly, JVM tests and lint passed.
- Existing host tooling suite: all 24 tests passed.
- `UsbAgentTransportTest`: both physical Android tests passed. Binary frames with
  NUL, CR/LF, XON/XOFF, escape and high-bit bytes survive both PTY directions.
  Packaged serial Agent opens the app-owned PTY and reports running on Android.
- `setup/esp32-usb.sh build` and upload passed; flashed data hashes verified.
  Firmware application uses 43,364 bytes RAM (13.2%) and 342,881 bytes flash
  (26.2% of default application partition). Original board flash backup retained
  privately; no personal phone storage/apps accessed.
- User connected the reference CP2102 board directly to the reference Realme
  phone. Android enumerated the expected bulk IN/OUT endpoints; USB permission
  was granted manually. App UI reported Running · USB · 115200 baud.
- `MicroRosAgentTest#esp32ReceivesPhoneBatteryAndRepliesAfterAgentRestart` with
  `usbConnected=true`: **1 test passed, 0 skipped, 0 failures**, test time 13.341s.
  Real phone battery messages reached the MCU; its String acknowledgements reached
  the phone's native ROS subscriber. Stopping the Agent preserved the sensor
  session; after draining old messages and capturing a new receive baseline,
  restarting the serial Agent produced multiple new acknowledgements.
- Normal app startup restored after removing the instrumentation APK: battery
  publishing and USB Agent active. User physically unplugged/replugged the board,
  selected Start USB agent and granted access. The app again showed Running USB;
  a new PC ROS subscription received a fresh battery acknowledgement after this
  reconnect. No reflashing or PC Agent was needed. The normal phone Display
  subscriber was then restored and its visible acknowledgement continued updating.
- The MCU serial firmware has no Wi-Fi transport/configuration. PC USB cables
  were removed during the interoperability trial. Authorized wireless ADB was
  used only for instrumentation/development; no PC Agent participated.

Initial PTY test cleanup exposed a test-reader exception when destroying its
process; handling expected stream closure fixed it. An ADB transport switch
interrupted one test dispatch; rerunning on a stable transport passed. These
were not recorded as successful interoperability trials.

## Boundaries

Real typed USB interoperability and software Agent restart are proven on one
board/phone. Manual Start after physical unplug/replug also recovered real traffic.
Sustained throughput/latency,
one-hour endurance, fully offline phone DDS discovery, another USB adapter/phone
and power limits need separate
qualification. Android permission denial/no-device messages are implemented, not
all branches physically exercised. Explicit Start after reconnect is required.
Graph-manager metadata and actuator command expiry remain pending.

Configured UART capacity is 11,520 bytes/s per direction before XRCE overhead,
not a throughput measurement or a head-to-head Wi-Fi benchmark. Higher baud rates
were not tested. See [ESP32-USB.md](../ESP32-USB.md) for reproducible use.
